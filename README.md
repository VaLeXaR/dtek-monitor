# 🪫 DTEK Monitor

Автоматичний моніторинг відключень електроенергії у Києві зі сповіщеннями в Telegram про аварійні та екстрені відключення.

## 💖 Підтримка

Якщо проєкт корисний для вас не забудьте поставити ⭐️ та [підтримати донатом](https://send.monobank.ua/jar/3QTpZrNn2T).

## 📋 Опис

Проєкт перевіряє інформацію на сайті «ДТЕК Київські електромережі» для вказаної вулиці та будинку в Києві. При виявленні аварійного або екстреного відключення він надсилає сповіщення в Telegram. Планові відключення не спричиняють сповіщень.

Моніторинг можна запустити через Docker або GitHub Actions. Стандартний інтервал перевірки — 10 хвилин.

## ✨ Можливості

- 🤖 Автоматична перевірка статусу електропостачання для адреси в Києві кожні 10 хвилин.
- 📱 Надсилання сповіщень в Telegram про аварійні та екстрені відключення.
- ♻️ Оновлення існуючого повідомлення замість створення нових (одне повідомлення на день).
- 🗑️ Видалення сповіщення після завершення аварійного чи екстреного відключення.
- 📊 Відображення причини, часу початку та очікуваного часу відновлення.
- 🔄 Автоматичний запуск через Docker або GitHub Actions.

## 🚀 Швидкий старт

### 1. Форк репозиторію

Натисніть кнопку "Fork" у правому верхньому куті сторінки репозиторію.

### 2. Створення Telegram бота

1. Відкрийте [@BotFather](https://t.me/BotFather) в Telegram.
2. Відправте команду `/newbot`.
3. Вкажіть ім'я та username для бота.
4. Збережіть отриманий токен (формат: `123456789:ABCdefGHIjklMNOpqrsTUVwxyz`).

### 3. Отримання Chat ID

1. Відправте будь-яке повідомлення вашому боту.
2. Відкрийте в браузері `https://api.telegram.org/bot<YOUR_BOT_TOKEN>/getUpdates`.
3. Знайдіть значення у форматі `"chat":{"id":123456789}` — це ваш Chat ID.

### 4. Налаштування Secrets

Перейдіть в **Settings** → **Secrets and variables** → **Actions** вашого форкнутого репозиторію та додайте наступні secrets:

| Secret               | Опис                                          | Приклад                                |
| -------------------- | --------------------------------------------- | -------------------------------------- |
| `TELEGRAM_BOT_TOKEN` | Токен бота від BotFather                       | `123456789:ABCdefGHI...`                |
| `TELEGRAM_CHAT_ID`   | ID чату в Telegram                            | `123456789` або `-123456789` (для каналу) |
| `STREET`             | Назва вулиці в Києві, як на сайті ДТЕК         | `Хрещатик`                             |
| `HOUSE`              | Номер будинку                                 | `1`                                    |
| `PAT`                | Токен GitHub для збереження стану в репозиторії | [Інструкція](#створення-pat)           |

#### Створення PAT

1. Перейдіть в **Settings** → **Developer settings** → **Personal access tokens** → **Fine-grained tokens**.
2. Натисніть **Generate new token**.
3. Підтвердіть доступ одним із запропонованих методів, наприклад `Use GitHub Mobile`.
4. Вкажіть назву токена, наприклад `dtek-monitor`.
5. Встановіть термін дії (або `No expiration` на свій розсуд).
6. Оберіть **Repository access** → `Only select repositories` та оберіть клонований репозиторій.
7. Натисніть **+ Add permissions** → відмітьте `Read access to metadata` та `Read and Write access to code`.
8. Натисніть **Generate token** та скопіюйте токен.

### 5. Запуск Actions

1. Перейдіть на вкладку **Actions**.
2. Знайдіть та відкрийте workflow з назвою **"Run power outages monitor"**.
3. Праворуч вгорі натисніть **Run workflow** → і ще раз на **Run workflow** всередині випадного меню.

## 🐳 Запуск через Docker

Потрібні Docker Engine та Docker Compose. Node.js і Chromium встановлюються в образі автоматично.

### Налаштування

Якщо `.env` ще немає, створіть його з прикладу:

```bash
cp .env.example .env
```

Заповніть `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `STREET` та `HOUSE`.
У `STREET` вкажіть назву київської вулиці так, як вона зазначена на сайті ДТЕК.
Змінна `CHECK_INTERVAL_SECONDS` задає паузу між перевірками в секундах; стандартне значення — `600` (10 хвилин).

### Постійний моніторинг

```bash
docker compose up -d --build
```

Перша перевірка виконується одразу після запуску, наступні — через задану паузу після завершення попередньої.
Контейнер автоматично запускається після перезапуску Docker, якщо його не було зупинено вручну.

```bash
# Перегляд логів
docker compose logs -f monitor

# Зупинка
docker compose down

# Перезбірка після оновлення коду або .env
docker compose up -d --build
```

Стан останнього Telegram-повідомлення зберігається у volume `monitor-state` і залишається після перезапуску або перезбірки контейнера.
Команда `docker compose down -v` видаляє цей стан.
Файл `artifacts/last-message.json` із репозиторію не переноситься у volume автоматично: перший запуск починає з нового стану.
Файл `.env` передається контейнеру під час запуску та не потрапляє в образ.

### Разова перевірка

```bash
docker compose build
docker compose run --rm monitor node ./src/monitor.js
```

Перед разовою перевіркою зупиніть постійний моніторинг командою `docker compose stop monitor`, щоб два процеси не оновлювали одне повідомлення одночасно.
Відновити його можна командою `docker compose up -d`.

## 🛠 Локальний запуск

### Вимоги

- Node.js (версія вказана в `.nvmrc`)
- npm

### Встановлення

```bash
# Клонування репозиторію
git clone https://github.com/YOUR_USERNAME/dtek-monitor.git
cd dtek-monitor

# Встановлення залежностей
npm ci

# Встановлення Playwright залежностей
npx playwright install chromium
```

### Налаштування

Створіть файл `.env` в кореневій директорії (скористуйтесь `.env.example`) з вмістом такого штибу:

```env
TELEGRAM_BOT_TOKEN=123456789:ABCdefGHIjklMNOpqrsTUVwxyz
TELEGRAM_CHAT_ID=-12346789
STREET=Хрещатик
HOUSE=1
```

### Запуск

```bash
# Для разового запуску
npm run start

# Для автоматичного перезапуску при зміні коду
npm run watch

# Ізольовані тести без звернень до DTEK і Telegram
npm test
```

## 🔍 Як це працює

1. **Отримання інформації**: Скрипт використовує Playwright для відкриття сайту ДТЕК та виконання AJAX-запиту з вказаною адресою.
2. **Перевірка відключень**: Аналізуються дані про наявність відключень (причина, час початку, час завершення).
3. **Відправлення повідомлення**: При виявленні аварійного або екстреного відключення формується повідомлення та відправляється в Telegram.
4. **Оновлення повідомлення**: Якщо повідомлення вже було відправлено сьогодні, воно оновлюється замість створення нового.
5. **Видалення повідомлення**: Після завершення аварійного або екстреного відключення попереднє повідомлення видаляється без окремого сповіщення про скасування.
6. **Збереження стану**: Інформація про останнє повідомлення зберігається у файлі `artifacts/last-message.json`. У Docker цей файл знаходиться у volume; у GitHub Actions він комітиться в репозиторій.

## ⚙️ Налаштування

### Зміна частоти перевірки

Для Docker змініть `CHECK_INTERVAL_SECONDS` у `.env` та виконайте `docker compose up -d`, щоб застосувати нове значення.

Для GitHub Actions відредагуйте cron вираз у файлі `.github/workflows/monitor.yml`:

```yaml
schedule:
  - cron: "*/10 * * * *" # Кожні 10 хвилин
```

Приклади:

- `*/30 * * * *` - кожні 30 хвилин
- `0 * * * *` - щогодини
- `0 */2 * * *` - кожні 2 години

### Додавання декількох адрес

Для моніторингу декількох адрес у Києві створіть окремі репозиторії або дублюйте workflow з різними secrets.
